# Аудит UI-паритета Python → C# (22.11.2026, живое тестирование)

Дополнение к [FUNCTION_PARITY_AUDIT_20261121.md](FUNCTION_PARITY_AUDIT_20261121.md) (там — статический код-аудит; здесь — **живой обход обеих запущенных программ** с UIA-дампами, скриншотами и кликами, плюс параллельный код-аудит меню/диалогов/хоткеев).

## Условия прогона

- Эталон: `python/main.py`, PySide6 6.12, версия 0.66.4, локальная SQLite-база.
- Порт: `GMC-Smeta-Next.exe` (Debug, net10.0-windows), SQL Server `GmcSmetaPilot_Cutover_20261120_160840` (подключение через `_tools/run_csharp.ps1`, профиль `%APPDATA%\GMC-Smeta-Next\sql-profiles.json`).
- Данные в базах **разные** (эталон: «Героев Хасана 7 / Договор»; порт: «ДНС 1.3 / Договор — устройство противодымной вентиляции», документ **подписан**). Сравнивалась структура UI, не содержимое.
- Оба окна разворачивались в максимизированное состояние перед каждым снимком.

## Как воспроизвести

```powershell
# 1. Запустить обе версии, открыть по одному документу в каждой
python main.py          # из python\
powershell -File _tools\run_csharp.ps1

# 2. Полный обход: 5 вкладок x 2 версии — скриншоты (_shots\audit\),
#    дампы контролов (_tools\audit_state\), diff-отчёт
powershell -File _tools\audit_parity.ps1 -SkipLaunch

# 3. Отдельные инструменты
powershell -File _tools\audit_menu_dump.ps1 -ProcName GMC-Smeta-Next -OutPath _tools\audit_state\cs_actions_menu.txt
powershell -File _tools\audit_snap.ps1 -ProcName python -OutPath _shots\x.png
powershell -File _tools\audit_click_any.ps1 -ProcName python -Text "Смета" -ControlType CheckBox   # клик по тексту/id
powershell -File _tools\audit_dump_controls.ps1 -ProcName python -OutPath _tools\audit_state\dump.txt
```

Скрипты: `audit_parity.ps1` (оркестратор), `audit_menu_dump.ps1`, `audit_snap.ps1`, `audit_click_any.ps1`, `audit_click_item.ps1`, `audit_dump_controls.ps1`, `audit_dump_tree.ps1`. Дампы `audit_state\*.txt` и скриншоты в репо не хранятся (`.gitignore`), регенерируются скриптами.

**ПКМ по дереву объектов** в C# на практике не открывается (эталон: Новый объект / Создать допсоглашение… / Сохранить в Excel·PDF… / Сравнить… / История изменений… / Удалить договор…). Меню в коде есть (`MainWindow.xaml.cs:862-964`) и гасится политикой `SqlWritesEnabled` вне `GmcSmetaPilot_*` (`MainWindow.xaml.cs:864-870`); база прогона пилотная, поэтому вероятная причина на экране — состояние «Подписан» документа и/или политика. Требуется код-проверка пути блокировки.

**Меню «Действия» — точные составы** (дампы `_tools/audit_state/py_actions_menu.txt`, `cs_actions_menu.txt`):
- Эталон (договор, runtime): 18 пунктов; в коде 20 — «Создать копию КП (вариант)…» и «Сделать договором…» контекстно скрыты для договора.
- C# (договор): 20 пунктов всегда, включая скрытые у эталона; **+** «Обновить из SQL Server», «Пересортировать строки КП (запись)…»; **−** «Сохранить ссылку на расчёт в папку…».

## Баги C#, найденные при обходе

1. «Закупки»: нелокализованные/отладочные комбобоксы **«ProcurementSupplie ▾», «ViewChoice ( Code = ▾», «ViewChoice ( Code = КР. Lal ▾»** — сырые названия контролов в пользовательском тулбаре.
2. Тулбар «Закупок» уезжает за край экрана (горизонтальный скролл, правые контролы обрезаны).
3. Поле поиска «Материалов» оторвано от тулбара (одинокое поле под «Наценка выделенным…»).
4. Нижние карточки КС: обрыв текста с «…» («без НДС 570 5…», «остаток…», «(подписано…)»).

## Расхождения дизайна

- **Сетка**: эталон — компактные строки (~26 px), вертикальные линии колонок, розовая подсветка пустых цен и красные прочерки «—»; C# — строки вдвое выше, групповые строки спрямлены («ВД1 › Оборудование» одной строкой вместо иерархии с ▾), подсветки пустых значений нет.
- **Колонки «Материалов»**: эталон «Цена клиенту / Сумма клиенту / Закуп за ед. / Закуп сумма / Наценка % / Маржа / Факт по счёту» → C# «Мат: розн. за ед. / Мат: розница / Мат: закуп за ед. / Мат: закуп / Наценка % / Мат: маржа»; потеряны «№» и «Факт по счёту».
- **Под-вкладка «СМР»**: в эталоне существует, но скрыта (`ui/cost_view.py:174`, `sec_btns[1].hide()`) — в C# показана. Для строгого паритета скрыть.
- **Нижние панели «Сметы»**: эталон «Материалы / Монтаж, СМР / Транспорт / ИТОГО» vs C# «Строки сметы (без НДС) / Транспорт / Пусконаладка / ИТОГО».
- «Выдача» — полный редизайн: эталон = мастер-список «Ведомости объекта» + пустое состояние с объяснением; C# = одностраничник с шагами ①-④, «Выдать сейчас», Excel/PDF.
- Только в C#: статусбар («Смета загружена»), счётчик «150 позиций · 30 систем», баннер-подсказчик «ПОДРЯДНО» на КС, третья кнопка в тулбаре сайдбара.
