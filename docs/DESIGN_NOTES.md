# DESIGN_NOTES — визуальный паритет WPF ↔ Python (рабочий документ Codex)

Этот документ ведёт агент, который делает дизайн. Здесь: правила работы,
актуальный список расхождений и журнал изменений. Правила менять нельзя.

## Правила (обязательные)

1. **Работа только в main**, каждый коммит — сразу `git push origin main`.
2. **Только `*.xaml`** (включая `App.xaml`): цвета, шрифты, отступы, размеры,
   шаблоны элементов, стили. **Не трогать** `*.cs`, `*.csproj`, биндинги,
   `x:Name`-элементы (они используются из кода), `Visibility` (это поведение),
   логику и структуру DataContext. Переименование/удаление существующих
   `x:Name` запрещено — сломается сборка.
3. **Сборка обязана проходить** перед каждым пушем:
   `dotnet build csharp/GmcSmeta.slnx` (0 ошибок; warnings допустимы, новых не добавлять).
4. **Один блок — один коммит** с понятным сообщением (`design: ...`) и пушем.
5. Если для дизайна нужна правка кода — **не делать самому**: записать в конец
   этого файла раздел «Нужна поддержка кода» (что и зачем), запрос выполнит
   основной агент на main.
6. Эталон оформления — Python `python/sql-server-current/smeta/ui/theme.py`
   (роли шрифтов, цвета) и соответствующие экраны `smeta/ui/*.py`.
   Проверка окна: `GMC-Smeta-Next.exe --smoke-test` при заданном
   `GMC_SMETA_SQL_CONNECTION` или запуск через лаунчер на рабочем столе.
7. Базу не переносить, рабочие серверные базы не открывать; тестовая база —
   только `GmcSmetaPilot_*` на localhost.
