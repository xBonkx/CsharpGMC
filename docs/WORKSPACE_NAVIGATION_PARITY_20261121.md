## Технические решения

- MainWindow.xaml и MainWindow.Metal.cs не меняются до интеграции PR #26.
- Новые окна реализованы отдельными C# WPF-классами без новой модели данных.
- App.xaml.cs вызывает изолированный MainWindow.Navigation.cs; существующие команды металла, ПТО и писем не перезаписываются.
- SQL Server — единственный backend. Записи в организациях/тегах и каталоге ограничены GmcSmetaPilot_*, транзакцией SERIALIZABLE, проверкой meta.rev и change_log.
- Глобальный поиск параметризован, экранирует специальные символы LIKE, разбивает запрос на слова (до 6), ограничивает результат 60 записями на категорию и не загружает все сметы в память.
- Каталог использует страницы по 200 записей + 1 для проверки следующей страницы; последняя цена и полная история извлекаются из текущих позиций смет, как в Python builder.py, а не из отдельного кэша цен. Журнал — максимум 3000 событий, без удаления аудита.
- Слияние дублей номенклатуры сначала переносит записи price_history и ссылки positions, а затем удаляет исходный catalog_items.
- При удалении организации проверяются привязанные договоры; не происходит скрытого изменения contract.company_id. При удалении тега запрещена потеря правил у документов; ссылки на тег только у объектов очищаются, как в Python.
- Не выполняются автоматические повторные записи после возможного неопределённого исхода COMMIT.

## Непроверенные сценарии (жёсткий gate перед merge)

1. Windows Release build и офлайн-тесты должны успешно завершиться на точном HEAD SHA.
2. Реальный GUI на 1920×1080 и 1366×768: диалоги, сортировка, Ctrl+P, Ctrl+N, F2, F5, переходы, архив, корзина, меню металла после PR #26.
3. SQL пилот GmcSmetaPilot_*: поиск на 2500–10000 строк, каталог 10–50 тыс. позиций, тысячи объектов/документов; планы запросов и измерения.
4. Два клиента: изменение одинакового справочника, конкурентный meta.rev, конфликты и откаты, обрывы сети, неизвестный COMMIT, повторный запуск.
5. Ролевое ограничение видимости: SQL права, объекты и контракты разных пользователей. Локальный режим ПТО не заменяет серверные права.
6. После issue #38 подключить реальные пункты людей/приказов. Сейчас пункт намеренно неактивен.
7. После PR #31 согласовать публичный API фокусировки позиции по ID. Сейчас Ctrl+P открывает смету, но строку не подсвечивает.
8. В каталоге нужен режим выбора нескольких записей для вставки в систему; отображение логотипов в экспорте КП после сохранения требует регрессии, а в настройках ещё отсутствуют шрифты, справка и резервные копии.

GitHub Actions в этом сеансе завершались через несколько секунд с выводом jobs: steps=null, logs_url=null и BlobNotFound при запросе логов. Это не является ни успешной сборкой, ни доказательством ошибки кода. Приёмку не проводить до выполнения реальных шагов Windows CI.

Изменения не объединены с main, PR оставлен Draft.
