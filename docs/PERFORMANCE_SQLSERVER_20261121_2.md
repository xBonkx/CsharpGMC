## Подтверждённые проблемы по исходному коду

1. `SqlServerProcurement.BuyRows`: пять коррелированных запросов к `dbo.movements` (два для прихода, два для выдачи, один для последней даты выдачи), каждый вычислялся для строки закупки. SQL Server мог оптимизировать их на своём плане, поэтому **не следует** заявлять умножение числа сетевых round-trip или конкретное ускорение без фактического плана.
2. `ProcurementPane.Reload` синхронно выполнял `BuyRows` и `SystemChoices` на диспетчере WPF при создании и обновлении окна, а также после записей.
3. `EstimateView.QueueSave`: после исключения SQL сохранившаяся ревизия могла быть неопределённой (соединение могло оборваться после COMMIT), но `_serverConflict` не выставлялся.

## Изменения

- `SqlServerProcurement.BuyRowsQuery()`: **одно чтение с группировкой по `position_id`**, ограниченное `contract_id=@id` ещё внутри подзапроса. Сохранены четыре прежних отдельных суммы: `in - back_supplier`, `out - back`; последняя дата `out`, прежний порядок и порядок колонок для `MapBuyRow`.
- `ProcurementPane.ReloadAsync`: чтения выполняются в `Task.Run`, а отображение и фильтры остаются на UI-потоке. Версионный счётчик сбрасывает устаревшие ответы при быстром переключении/повторном обновлении. Вызвавшие обновление `async`-методы теперь дожидаются результата до продолжения.
- Отдельное получение ревизии при пакетной операции и удалении движения перенесено в фоновую задачу; получение ID объекта при выдаче также перенесено с UI-потока.
- `EstimateView.QueueSave`: исключение помечает конфликт сервера и останавливает последующую запись до авторитетной синхронизации.
- Офлайн-регрессия в `ProcurementReadAndSupplierTests` проверяет контрактный scope SQL, четыре исходных типа движений, дату, отсутствие пяти коррелированных агрегатов и порядок чтения.

## Проверки, ещё необходимые перед признанием ускорения

- Windows build и офлайн-тесты — проверять отдельно в GitHub Actions для новой версии.
- На **`GmcSmetaPilot_*`**: сравнить старый/новый `BuyRows` по каждой колонке для позиций без движений, частичных приходов, возвратов, выданных сверх КП, нескольких систем и пустых систем.
