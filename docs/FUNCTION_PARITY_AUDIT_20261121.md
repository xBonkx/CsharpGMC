## Проверка по реальным доказательствам

- **Реализованная операция:** в C# существует SQL-запись/чтение и UI-обработчик.
- **Частичный перенос:** есть упрощённый аналог (например, типовой Excel КС вместо заказных шаблонов или импорт строк вместо полного импорта КП).
- **Не найдено:** нет отдельного модуля/команды в просмотренных C#-исходниках; проверить отсутствующий пользовательский сценарий и не выдавать отсутствие имени файла за формальное доказательство.
- **Проверено:** для конкретного сценария есть офлайн-тест **и** прогон на SQL Server-пилоте с фактическим результатом; для интерфейса и экспорта дополнительно нужен визуальный контроль.

## Главные риски и ограничения оценки

1. **Смешение «реализовано» и «принято».** 326 тестов не покрывают весь Python UI, сетевые гонки, печать и реальные SQL-транзакции.
2. **Разные пользователи видят разные функции.** Основной сметчик может не пользоваться ПТО, но для «полной замены Python» эти модули нельзя забыть без явного исключения.
3. **Архитектурное правило SQL Server-only.** Исходные паспорта и ПТО использовали самостоятельные архивы (в том числе SQLite); их нельзя просто перенести с этим хранилищем в C#. Нужно отдельное проектное решение.
4. **Не трогать производственную БД.** Пилотное ограничение сохранять до отдельной процедуры cutover с резервной копией и возможностью отката.
5. **Нет честного числового процента** без согласованного набора сценариев и проверки; оценивать выполнение по F01–F12 в `ROADMAP.md`, а не по коду/коммитам.
