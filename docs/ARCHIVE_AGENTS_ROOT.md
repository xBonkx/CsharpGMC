# AGENTS.md — правила и карта задач для ИИ-агентов

Этот файл — точка входа для любого ИИ-агента, работающего в репо. Читай его перед первой задачей.

## Где лежат задачи

| Файл | Что там | Когда использовать |
|---|---|---|
| [csharp/docs/MASTER_TODO.md](csharp/docs/MASTER_TODO.md) | **Единый актуальный реестр замечаний, статусов, доказательств и остатков** | Обязательно до и после каждого блока работ |
| [csharp/docs/SMALL_TASKS.md](csharp/docs/SMALL_TASKS.md) | **Мелкие задачи (S-xx) в формате «взял → сделал → готово когда»** | Основной источник для коротких задач: бери первую `Статус: TODO` сверху |
| [csharp/docs/ROADMAP.md](csharp/docs/ROADMAP.md) | Стратегический реестр F01–F12 с критериями «готово» | Крупные работы, планирование; мелкую задачу вырезай из F-задач |
| [csharp/CURRENT_TASK.md](csharp/CURRENT_TASK.md) | Журнал текущего чекпоинта агента | После каждой задачи добавь короткую запись |
| [csharp/docs/UI_PARITY_AUDIT_20261122.md](csharp/docs/UI_PARITY_AUDIT_20261122.md) | Аудит UI-паритета: 10 пробелов + 4 бага | Первоисточник для UI-задач |
| [csharp/docs/PERFORMANCE_OPEN_20261122.md](csharp/docs/PERFORMANCE_OPEN_20261122.md) | Перф-анализ открытия, план P1–P4 | Первоисточник для перф-задач (P4 сделан) |

**Формат задачи в SMALL_TASKS.md:** ID, статус (TODO/IN PROGRESS/DONE), файлы, что сделать, «готово когда», команда проверки. Закончив — обнови статус по правилам MASTER_TODO; DONE только после фактической приёмки.

## Рабочий цикл (мелкая задача)

1. Сверь `csharp/docs/MASTER_TODO.md`; выбери актуальный ID из реестра и связанного исходного списка (SMALL_TASKS для мелких задач).
2. Поменяй статус на `IN PROGRESS` в том же коммите.
3. Реализуй. **Питон-эталон `python/` — только читать**, не изменять.
4. Проверь (см. «Проверка» ниже) — всё зелёное.
5. Обнови фактический статус, MASTER_TODO, исходный TODO и `CURRENT_TASK.md`, коммит на русском, **push в `main` сразу** (правило владельца). Не копить недопушенные коммиты.

- Перф-правки: `_tools/audit_open_timing.ps1` (живой замер) + `RemoteSqlBench` (SQL-фаза).

## Правила репо (нарушать нельзя)

- **Только SQL Server.** Новые SQLite-функции/миграции запрещены. Запись в БД разрешена только в базы `GmcSmetaPilot_*` (зашито в коде, `SqlServerWorkspace.RequirePilotDatabase`).
- **Кодировка:** не редактировать исходники через PowerShell `Set-Content`/`Get-Content` — перекодирует кириллицу в mojibake. `.ps1`-скрипты с кириллицей сохранять в UTF-8 **с BOM** (PowerShell 5.1 иначе читает как ANSI).
- **Коммиты:** сообщение на русском, минимальный дифф, одна логическая задача = один коммит. Push — в `main`.
- **Не трогать** без явного указания: `python/` (эталон), `_backup/`, политики записи пилота (`SqlWritesEnabled`).
- Эталон поведения — **python 0.66.4** (`python/smeta/`): спор «как правильно» решается сверкой с ним, а не вкусом.
- Незавершённые эксперименты не оставлять в main: недоделанное — в отдельную ветку или не коммитить.

## Карта кода (кратко)

- `csharp/src/GmcSmeta.App/` — WPF: `MainWindow*.cs` (навигация, дерево, SQL-профили), `EstimateView*.cs` (редактор сметы: `.xaml.cs` + партиалы), `ProcurementPane`, `ShipmentsPane`, `ActsEditorView`, `CostSummaryPane`.
- `csharp/src/GmcSmeta.Core/` — ядро: `Domain/Estimate.cs` (ридер сметы, общий с SQLite-тестами — **SQL тут должен работать и на SQLite: COALESCE, не ISNULL**), `Db/SqlServer*.cs` (SQL-операции), `Db/SqlServerUndo.cs` (undo-снапшот).
- `_tools/` — скрипты автоматизации (UIA, бенчмарки, аудит-паритет).

## Обязательное непрерывное ведение единого реестра (25.11.2026, правило владельца)

- **Главный источник статусов — `csharp/docs/MASTER_TODO.md`.** Перед любым заданием (включая «продолжи», аудит, багфикс, рефакторинг, дизайн, оптимизацию, тестирование) проверить актуальный main, прочитать нужные строки реестра и исходный TODO. Не создавать независимые списки без регистрации ID в MASTER_TODO.
- До реализации зафиксировать взятые ID, агент/ветку/дату (IN PROGRESS); не брать чужие активные задачи без согласования. Новое замечание получает устойчивый уникальный ID, приоритет, источник/файлы, критерий приёмки; дубли связывать с каноническим ID, не удалять историю. Исходные подробные аудиты сохранять.
- **Каждый блок изменений = код/тесты + актуализация MASTER_TODO, соответствующего исходного TODO и CURRENT_TASK в том же коммите.** По каждому затронутому ID записать статус, что именно сделано, доказательство (коммит/файл/тест, дата и фактический результат), конкретный остаток/блокер, следующий шаг. Если блок ничего не закрывает, зафиксировать PARTIAL или BLOCKED; не отмечать все задачи блока одним общим DONE. Для нового коммита допустима ссылка на изменённый файл/тест; после публикации подтверждать SHA. Обновлять связанные Issues и ROADMAP, если затронут их объём; не дублировать задачи.
- Статусы: UNVERIFIED (не выяснено), NOT STARTED (проверено отсутствие реализации), IN PROGRESS, PARTIAL, CODE READY (код готов, приёмка открыта), DONE (все необходимые проверки фактически пройдены), BLOCKED (причина), DUPLICATE (канонический ID), N/A (обоснованное согласованное исключение). Чекбокс закрывать только при DONE. Не выдавать статическую проверку за сборку, запуск тестов, GUI, SQL Pilot или замеры. При регрессии переоткрывать ID.
- После каждого блока пересчитать сводку по статусам и по спискам, отдельно число оставшихся кодовых правок, задач приёмки и неизвестных статусов; не считать окна/Issues/ROADMAP вторично. Проверить уникальность ID, сумму строк и статусов, ссылки, сохранение чужих изменений. При параллельных изменениях main перечитать свежий реестр и объединить строки, не перетирать чужие статусы и не использовать force push.
- Перед публикацией выполнить доступные проверки и честно указать невыполненные; после push проверить удалённый main и сообщить SHA, IDs, число полностью закрытых, частичных, ожидающих приёмки и остаток. Если доступ к Windows/SQL отсутствует, это не основание ставить DONE. Рабочую БД не трогать.
- Эти требования распространяются на все чаты и агентов проекта и имеют приоритет над старой формулировкой «Статус → DONE» после любого блока. Вести реестр постоянно, а не только при очередном аудите.
