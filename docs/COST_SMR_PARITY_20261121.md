## Матрица переключений СМР

| Из → В | `sum` | `pos` | `percent` | `systems` |
| --- | --- | --- | --- | --- |
| `sum` | сохранить | разрешено* | блокировать | блокировать |
| `pos` | разрешено* | сохранить / обновить* | блокировать | блокировать |
| `percent` | блокировать | блокировать | оставить без конвертации | блокировать |
| `systems` | блокировать | блокировать | блокировать | оставить без конвертации |

**`*` Общие ограничения:** подписанный документ, КП-этап или главный КП с управлением суммой по этапам — смену режима блокировать. Для `pos → sum` сохранить стоимость СМР из позиции, для `sum → pos` перенести внутренние `work_sell` в `work_price` существующим SQL-механизмом. В `percent` и `systems` исходные поля остаются нетронутыми.

## Защита и тесты

- Вновь созданные денежные SQL-операции требуют **`GmcSmetaPilot_*`** и сравнивают `meta.rev` до записи в **`SERIALIZABLE`**-транзакции. Изменения позиций и расходов привязаны к `contractId`, не к одному пользовательскому `rowId`.
- При ошибке связи на COMMIT результат **неопределённый**: повторную неидемпотентную запись автоматически не выполнять.
- Off-line xUnit: тестовый набор 2800 строк для группировок и суммы, значения на границах копеек сверяются с Python-`round(double, 2)`, дополнительные тесты на группировки, пустые системы, стоимость транспорта, коэффициенты наценок.
- **Не проверено физически в этой среде:** `dotnet build` WPF/.NET 10, реальное соединение с тестовой `GmcSmetaPilot_*`, 2 клиента, 2500+ строк, UX-клик-тест и парные скриншоты 1920×1080/1366×768. Результат GitHub Windows CI нужно фиксировать по конкретному HEAD после завершения.

## Оставшиеся ограничения до полной приёмки

1. Сверка итогов и НДС по одному живому договору: `decimal` в UI и Python `float` в хранилище могут расходиться на пограничных значениях. Декларация «до копейки» возможна только после фактических парных тестов.
2. Переходы из/в `percent` и `systems` сознательно запрещены, пока не доказана конвертация без потерь.
3. Экспорт себестоимости в PDF и паритет внутренней печатной формы, системный выбор по поиску, горячая клавиша Delete и опции массовой переоценки в UI требуют дальнейшей реализации.
4. Запись в production SQL Server запрещена; разрешения расширять не нужно.
