# GMC-Смета C#: запуск ноутбука по LAN без локального SQL Server

Задача №21, 21.11.2026. Ветка: **feature/remote-sql-testing**. Полный сценарий — ноутбук с Windows и .NET 10 запускает WPF-приложение, а SQL Server и тестовая база **GmcSmetaPilot_Laptop** находятся на домашнем ПК. SQL Server, SQL Express и SQLite на ноутбуке не требуются.

**Безопасность:** запрещено открывать порт SQL Server в интернет и делать проброс через роутер. Подключайтесь через доверенную домашнюю сеть. Только базы **GmcSmetaPilot_***, без production-данных. Не помещайте пароли в репозиторий, логи и командную строку.

## 1. Настройка домашнего компьютера

1. Найдите службу в **services.msc**: **SQL Server (MSSQLSERVER)** — экземпляр по умолчанию, **SQL Server (SQLEXPRESS)** — именованный. Можно проверить имя через SSMS: SELECT @@SERVERNAME; SELECT SERVERPROPERTY('InstanceName');.
2. Откройте **SQL Server Configuration Manager → SQL Server Network Configuration → Protocols for [экземпляр] → TCP/IP → Enabled = Yes**. Для SQL Server 2022 оснастка обычно SQLServerManager16.msc; для других версий номер отличается.
3. В свойствах **TCP/IP → IP Addresses** задайте фиксированный порт: очистите **TCP Dynamic Ports** для активного сетевого интерфейса/раздела IPAll и задайте **TCP Port = 1433** или другой свободный порт. Убедитесь, что порт не занят другим экземпляром. Перезапустите службу SQL Server и проверьте в ERRORLOG, что он слушает домашний IPv4, а не только localhost.
4. На домашнем ПК выполните в PowerShell команду **ipconfig**. Запишите IPv4 LAN-адаптера (например, 192.168.1.46). Не используйте VPN-IP, localhost или внешний IP. Желательно закрепить IP в DHCP роутера.
5. Настройте Windows Firewall на домашнем ПК под администратором. **Замените подсеть и порт на свои**, не разрешайте весь интернет:

~~~powershell
New-NetFirewallRule -DisplayName "GMC SQL LAN" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 1433 -Profile Private -RemoteAddress 192.168.1.0/24
~~~

Проверка: **Get-NetFirewallRule -DisplayName "GMC SQL LAN"**. Если остались другие разрешающие правила для SQL Server, проверьте, что они тоже ограничены доверенной LAN.

6. Через SSMS создайте базу **GmcSmetaPilot_Laptop** или восстановите в неё **обезличенный тестовый** backup существующей GmcSmetaPilot_*. При восстановлении: Databases → Restore Database → Device → тестовый .bak → Destination **GmcSmetaPilot_Laptop** → Files/Relocate → новые уникальные пути MDF/LDF. Не применяйте WITH REPLACE к существующей базе. Для SQL-скрипта восстановления сначала сделайте RESTORE FILELISTONLY и используйте WITH MOVE с новыми именами путей. **Нельзя автоматически копировать производственную базу**.
7. В SSMS убедитесь, что версия схемы 28 и есть ревизия:

~~~sql
USE [GmcSmetaPilot_Laptop];
SELECT [value] AS schema_version FROM dbo.meta WHERE [key] = N'schema_version';
SELECT [value] AS revision FROM dbo.meta WHERE [key] = N'rev';
~~~

Если dbo.meta отсутствует или версия не 28, восстановите правильную тестовую схему; не обходите проверку фиктивной строкой.

8. Для разных Windows-пользователей предпочтительнее **SQL Server Authentication**. В SSMS: сервер → Properties → Security → SQL Server and Windows Authentication mode, подтвердить и при необходимости перезапустить службу. Windows Authentication работает, когда домен, учётные записи и права действительно совместимы.

## 2. Отдельный SQL-логин только для тестовой БД

Под администратором SSMS выполните, заменив пароль самостоятельно (не храните его в скриптах):

~~~sql
USE [master];
CREATE LOGIN [gmc_laptop]
  WITH PASSWORD = N'<СЛОЖНЫЙ_ПАРОЛЬ_ЗАДАЙТЕ_САМИ>',
       CHECK_POLICY = ON, CHECK_EXPIRATION = OFF;
GO
USE [GmcSmetaPilot_Laptop];
CREATE USER [gmc_laptop] FOR LOGIN [gmc_laptop];
GRANT CONNECT TO [gmc_laptop];
GRANT SELECT, INSERT, UPDATE, DELETE ON SCHEMA::dbo TO [gmc_laptop];
GO
~~~

Эти права относятся только к одной изолированной БД. Не выдавайте sysadmin, db_owner, права миграций, CREATE или ALTER. Логин gmc_laptop не должен иметь других пользователей/разрешений в рабочих БД. Перед повторным исполнением команд проверяйте существование LOGIN/USER. Приложение редактирует dbo.meta.rev, журналы и таблицы, поэтому только SELECT недостаточно.

## 3. Проверка TCP с ноутбука

Оба компьютера в одной доверенной сети. В PowerShell ноутбука:

~~~powershell
Test-NetConnection -ComputerName 192.168.1.46 -Port 1433
~~~

Подставьте реальный IP/порт. **TcpTestSucceeded : True** подтверждает только доступ к TCP; успешность SQL-логина, прав и версии схемы проверяется отдельно. Если False, проверьте настройки TCP/IP, Firewall, адрес, Wi-Fi guest isolation, VPN, активную службу и фиксированный порт.

## 4. Установка и запуск на ноутбуке через ZCode

1. Создайте отдельный checkout GitHub **xBonkx/CsharpGMC** на ноутбуке. Для использования обновляющего EXE нужна **чистая ветка main**, в которую координатор предварительно сольёт PR №21 после CI. Для тестирования пока неслитой feature-ветки запускайте WPF напрямую через dotnet run.
2. Для сборки из GitHub установите **.NET 10 SDK** на ноутбуке. SQL Server устанавливать не нужно. Для self-contained выпуска SDK не требуется, но текущий обновляющий лаунчер собирает программу из исходников и поэтому использует SDK.
3. Лаунчер ищет репозиторий по переменной **GMC_SMETA_REPO**, текущему каталогу, рядом с EXE или в папках ZCode %USERPROFILE%\.zcode\workspace\*\CsharpGMC. Если не найден, в PowerShell задайте путь (значения примерные):

~~~powershell
$env:GMC_SMETA_REPO = "C:\Users\<вы>\.zcode\workspace\<идентификатор>\CsharpGMC"
~~~

4. Из корня проекта соберите обновлённый ярлык EXE:

~~~powershell
powershell -ExecutionPolicy Bypass -File .\csharp\tools\install-desktop-launcher.ps1
~~~

Или для запуска прямо из feature-ветки без обновления:

~~~powershell
dotnet run --project csharp/src/GmcSmeta.App/GmcSmeta.App.csproj
~~~

5. При запуске появляется диалог **«Подключение к SQL Server»**. Введите: название профиля «Дом»; IP домашнего ПК; фиксированный порт (обычно 1433); база **GmcSmetaPilot_Laptop**; авторизация **SQL Server Authentication**; логин **gmc_laptop**; пароль.
6. Нажмите **«Проверить подключение»**. Ожидается: TCP — ОК, вход — ОК, схема — ОК (версия 28). Затем **«Сохранить и подключиться»**. В заголовке приложения отображается SQL Server, а в строке подключения — тестовая база.
7. Для переключения серверов закройте приложение и выберите сохранённый профиль при следующем запуске. Пароль необязательно хранить: оставьте «Запомнить пароль» снятой и вводите его при запуске. Если отмечено, пароль хранится только в виде **Windows DPAPI CurrentUser ciphertext** в %APPDATA%\GMC-Smeta-Next\sql-profiles.json; перенос профиля на другую Windows-учётную запись требует повторного ввода пароля. Настройки переживают сборки и обновления.
8. По умолчанию используется **Encrypt=Mandatory; TrustServerCertificate=False**. Если домашний сервер с самоподписанным сертификатом, **только для тестов внутри доверенной LAN** можно явно отметить «Доверять сертификату сервера», согласившись с предупреждением. Для постоянной работы настройте доверенный сертификат и снимите галочку.

Если задана старая переменная окружения **GMC_SMETA_SQL_CONNECTION**, приложение работает в совместимом режиме без диалога. Уберите её, чтобы использовать профили; при любом способе запуска non-pilot БД блокируется на входе.

**Лаунчер:** перед синхронизацией проверяет текущую ветку, git status и возможность fast-forward; не делает git reset --hard, не стирает незакоммиченные файлы и не сливает divergent main автоматически. При конфликте выводит понятное сообщение, данные остаются нетронутыми. Для ZCode-веток используйте отдельный checkout main или dotnet run в feature.

## 5. Ручная двухклиентская приёмка

Подключите два Windows-компьютера к одной **GmcSmetaPilot_Laptop**. Проверьте фактическое имя базы перед редактированием.

| Действие | Ожидаемый результат |
|---|---|
| Оба открывают один договор | Оба видят данные тестового документа |
| Первый меняет количество | После перечитывания второй видит новое значение и итог |
| Меняют разные позиции | При изменении общей ревизии второй не затирает чужие правки, перечитывает и повторяет свою |
| Меняют одну позицию | Нет тихого last-write-wins, появляется отказ устаревшей ревизии |
| Сеть исчезает во время COMMIT | Не повторять запись автоматически при неопределённом исходе; восстановить сеть, перечитать сервер |
| Undo/Redo при параллельной работе | Проверка текущей rev; чужие изменения не уничтожаются |
| КП на 300, 2500, 10000 строк | Измерить время загрузки, рендера, сохранения и итогов |

Код уже использует Serializable-транзакции и сверку meta.rev в ряде операций, но эта таблица **не является отчётом о пройденных тестах**. Реальный двухклиентский тест, обрывы сети и нагрузочные замеры на домашнем SQL Server должны быть выполнены после проверки CI.

## 6. Типовые ошибки

- **TCP недоступен:** неверный IP, порт, TCP/IP, Firewall, гостевой Wi-Fi или отключённый SQL.
- **TCP есть, авторизация неуспешна:** отключён SQL Authentication, неверный пароль, ошибка TLS или SQL-права.
- **База не открывается:** отсутствует GmcSmetaPilot_Laptop, нет прав CONNECT/SELECT, база offline.
- **Схема несовместима:** dbo.meta отсутствует или schema_version отличается от 28.
- **Конфликт ревизии:** другой клиент сохранил правку, перечитайте документ; не перезаписывайте вслепую.
- **Лаунчер остановился до обновления:** ветка не main, есть изменения или main расходится; изменений он не удаляет.

## 7. Что проверено и ограничения

Автоматические offline xUnit проверяют конструирование строк, порт, пилот-ограничение, оба способа авторизации, TLS-значения и DPAPI на Windows. GitHub Actions Windows выполняет restore/build/выбранные offline тесты и сборку лаунчера — конкретный результат уточнять по запуску CI в PR.

**Не проверено автоматически:** подключение к пользовательскому домашнему серверу, живой запуск на ноутбуке, проверка прав в SQL Server, два реальных ПК, задержки Wi-Fi, конфликт COMMIT при обрыве и performance. Для измерений см. bench/README.md и csharp/docs/REMOTE_SQL_BENCHMARK.md. Записи и бенчмарки допустимы только на отдельной тестовой БД.
