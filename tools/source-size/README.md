# Локальный аудит исходников

Python 3.10+ и Git, без внешних пакетов и GitHub Actions. Из корня репозитория:

```powershell
python tools/source-size/source_size.py --ref HEAD
python tools/source-size/source_size.py --ref HEAD --base HEAD~1 --json source-size-report.json
python -m unittest discover -s tools/source-size -p "test_*.py" -v
```

`--repo` задаёт путь к локальному репозиторию. `--ref` и `--base` — существующие коммиты/ветки (для воспроизводимого baseline использовать полный SHA). Анализируются только файлы коммита, не незакоммиченные правки. Сравнение учитывает переименования, обнаруженные Git (`--find-renames`); нераспознанные перемещения и копии считаются новым путём. Существующий долг не блокируется: предупреждение при росте файла выше 1000 строк, отдельно выше 4000. Дополнительно предупреждает о росте суммарного размера partial-типа выше 1000 строк, даже если его части по отдельности малы. В JSON есть `warnings`, `partial_warnings`, `renames`, `project`; предупреждения не блокируют сборку. Отчёт не изменяет репозиторий или БД; JSON создаётся только при явном `--json`.

Считаются физические строки включая комментарии и пустые строки, UTF-8/UTF-8 BOM; неподдерживаемая кодировка вызывает ошибку вместо скрытого пропуска. Исключения: bin/obj, vendor/generated/third_party/thirdparty, типичные generated-суффиксы и заголовки auto-generated, ссылки и нерегулярные записи Git; список исключений выводится явно. Отчёт содержит топ-30, распределение по диапазонам и полный список файлов в JSON. Partial-группы приблизительные: namespace + имя типа + ближайший tracked .csproj (при нескольких проектах в каталоге явно неоднозначная группа, без проекта — прежние первые две части пути), суммируются целые файлы, не тело типа; несколько namespace в одном файле пропускаются. Вложенные типы, комментарии, raw strings, generic-арность и вложенные проекты могут искажать оценку. Это сигнал для ручного аудита, не точный Roslyn-анализ. Не используется как обязательный gate сборки.
