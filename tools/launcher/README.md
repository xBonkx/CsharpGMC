# ГМЦ-Смета — запуск и автообновление (Windows)

Один EXE на рабочем столе сразу запускает установленную WPF-программу, а
проверку обновления из **GitHub Releases** выполняет отдельный процесс. .NET SDK, git-клон и ручная сборка на компьютере пользователя
не нужны.

## Что происходит при запуске

1. Если программа уже установлена, лаунчер запускает сохранённую версию **без ожидания GitHub/GCM**. Отдельный невидимый экземпляр проверяет обновления и готовит их **для следующего запуска**; текущий сеанс не закрывается и не перезапускается.
2. Если установки нет, запускается прежний процесс загрузки GitHub Releases (с токеном для закрытого репозитория), проверки SHA-256, распаковки и первого запуска. Без релиза остаётся локальная сборка из git-клона.
3. `--update-only` принудительно проверяет и устанавливает релиз без запуска WPF; о сетевом отказе сообщает ошибкой. `--no-update` запускает установленную копию без фоновой проверки. `--check` и `--dev` сохранены.
4. От одновременной установки защищает именованный mutex. Версии распаковываются рядом, без замены файлов уже запущенного WPF. Настройки сохраняются отдельно в `%APPDATA%\GMC-Smeta-Next`.
5. Обновление самого лаунчера, очистка предыдущих сборок и резервный путь установки сохраняются.

**Приёмка остаётся открытой:** Windows Release build, офлайн/DNS/403, первичная установка, 2 одновременных запуска, self-update, откат, сохранность данных и проверка реальных времён открытия.

## Токен GitHub (закрытый репозиторий)

Скачивание файлов из закрытого репозитория требует авторизации. EXE берёт токен
в таком порядке:

1. переменная среды `GMC_SMETA_TOKEN` (или `GITHUB_TOKEN` / `GH_TOKEN`);
2. файл `%APPDATA%\GMC-Smeta-Next\github-token.txt` (одна строка — сам токен);
3. `git credential fill` — сохранённые учётные данные GitHub в Git Credential
   Manager (обычно там уже лежит токен после первого `git push`).

Токен нужен с правом чтения приватного репозитория (fine-grained: `Contents: Read`).

## Параметры запуска

    ГМЦ-Смета.exe --check        показать версии и выйти
    ГМЦ-Смета.exe --no-update    запустить установленную версию без сети
    ГМЦ-Смета.exe --dev          собрать локальный git-клон через .NET SDK
    ГМЦ-Смета.exe --help         справка

Переменные среды: `GMC_SMETA_RELEASES=owner/repo` (другой источник релизов),
`GMC_SMETA_NO_UPDATE=1`, `GMC_SMETA_NO_SELF_UPDATE=1`.

## Диагностика запуска

В PowerShell задайте отдельный каталог для одного прогона:

    $env:GMC_SMETA_STARTUP_TRACE_DIR = Join-Path $env:TEMP ("gmc-startup-" + [guid]::NewGuid())
    & "C:\путь\ГМЦ-Смета (обновить и запустить).exe" --no-update

CSV создаются отдельно для лаунчера и WPF, содержат только UTC, PID, фиксированные имена фаз, миллисекунды и monotonic ticks/frequency. По ticks можно сопоставить процессы на одном ПК. Время диалога подключения включает ожидание пользователя, probe измеряется отдельно. ContentRendered — сигнал WPF, не измерение физического кадра монитора. main_workspace_data_ready — готовность начальных списков, не готовность запрошенной сметы. Измерение начинается внутри процесса, не включает щелчок по ярлыку. После замера удалите переменную среды. Без неё трассировка не пишет файлы.

## Как выпустить новую версию

Релиз собирается workflow `.github/workflows/csharp-release.yml` по тегу `vX.Y.Z`:

    git tag v0.1.0
    git push origin v0.1.0

Workflow соберёт решение, прогонит офлайн-тесты, опубликует в релиз:

| Вложение | Назначение |
|---|---|
| `GMC-Smeta-Next-win-x64.zip` | автономная WPF-сборка (без .NET на компьютере) |
| `GMC-Smeta-Next-win-x64-fx.zip` | лёгкая сборка для компьютеров с .NET 10 Desktop Runtime |
| `GmcSmeta.Launcher.exe` | запускающий EXE (он же обновляет себя) |
| `SHA256SUMS.txt` | контрольные суммы, проверяются при скачивании |
| `version.txt` | тег релиза |

После публикации релиза пользователям достаточно запустить EXE на рабочем столе:
он скачает новую версию сам. Повторный запуск workflow для того же тега заменяет
вложения существующего релиза.

## Установка EXE на рабочий стол

Из корня репозитория:

    powershell -ExecutionPolicy Bypass -File .\tools\install-desktop-launcher.ps1

Скрипт публикует автономный одиночный EXE и кладёт его на рабочий стол
(`ГМЦ-Смета (обновить и запустить).exe`), сделав `.bak`-копию прежнего файла.
Другой путь и имя:

    ... -DestinationPath "C:\Users\user\Desktop\ГМЦ-Смета.exe"

Ярлык в меню «Пуск» создаётся с иконкой и путём к этому же EXE.
При установке вне рабочего стола создаётся также ярлык на рабочем столе.
Если нужен только EXE, используйте `-SkipShortcuts`. При самообновлении путь EXE
остаётся прежним, поэтому ярлыки не зависят от номера версии.

Обе сборки приложения и лаунчер используют исходный
`src/GmcSmeta.App/Assets/app.ico`. Проверка встроенных ресурсов PE
выполняется скриптом `tools/verify-brand-icons.ps1` перед локальной упаковкой
и установкой лаунчера.

## Локальная публикация (если GitHub Actions недоступен)

Если репозиторий закрыт и Actions не работают (лимит/оплата), релиз можно
собрать и опубликовать с этой же машины:

    powershell -ExecutionPolicy Bypass -File .\tools\publish-release.ps1 -Version 0.1.0

Скрипт собирает решение и тесты, публикует обе сборки и лаунчер, упаковывает
архивы, считает SHA-256 и создаёт/обновляет релиз `v0.1.0` через API GitHub
с использованием сохранённых учётных данных git. Флаг `-SkipTests` пропускает
тесты, `-Draft` публикует черновик.

В режиме локальной сборки запущенная копия `GMC-Smeta-Next.exe` держит
`GmcSmeta.Core.dll`, поэтому сборка невозможна, пока окно открыто. Лаунчер просит
окно закрыться штатно и ждёт до 15 секунд; принудительно процесс не убивается.
Git-клон должен быть на ветке `main` без незакоммиченных правок.


## Графический центр обновлений (WPF)

Обычный запуск сохраняет быстрый путь: существующая версия открывается сразу,
фоновая проверка остаётся скрытой. Для видимой проверки используйте ярлык
«ГМЦ-Смета C# (проверить обновления)» или параметр `--update-only`.
При первой установке окно также открывается автоматически. BAT оставлен только
для разработческой сборки, пользователю он не нужен.

Окно показывает установленную и доступную версии, этапы, фактически скачанные
МБ и процент (если известен размер), раскрываемые подробности и ошибки.
Отмена доступна до начала распаковки; во время смены состояния закрытие
блокируется. Архив без SHA-256 отклоняется. Новая сборка устанавливается в
отдельный каталог, installed.txt переключается после проверки EXE, прежняя
версия сохраняется. Текущий рабочий сеанс не перезапускается.
