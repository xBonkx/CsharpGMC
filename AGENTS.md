Минимум 5 относится к новым завершённым рабочим пакетам реализации, не к подзадачам-проверкам, уже готовому коду или документационному дроблению. Отдельно показывать T/A DONE и повышение родительских ID; если остались только приёмка/блокеры — назвать их без искусственных изменений. Обновлять рабочую очередь, MASTER_TODO, исходный TODO и CURRENT_TASK одним коммитом. Если новые глобальные ID появляются после среза, сначала разбить их в этой очереди с конечным критерием. Сохранять приоритеты, не добавлять функции без согласования.

 На команды «продолжай/дальше» брать максимально крупный, но проверяемый пакет конкретных ID (минимум 5 новых CODE READY за проход по уточнению владельца от 28.11.2026; PARTIAL, затронутые и уже готовые ID в этот минимум не входят; если объективный блокер не позволяет закрыть пять, прямо указать недостачу, без искусственного повышения статусов); сначала актуальные P0/P1 и остатки уже частично реализованных задач, затем P2 и остальной реестр. Для каждого ID сверять исходный критерий и текущий main, доделывать отсутствующий код, защиту, интеграцию и регрессионные проверки; не распыляться на несвязанные рефакторинги и не оставлять новые частичные блоки без необходимости. CODE READY только когда все требования к реализации выполнены, указаны доказательства и остаётся исключительно фактическая приёмка (build/test/WPF/DPI/SQL Pilot/экспорт/замеры); известный дефект или отсутствующая реализация остаётся PARTIAL/BLOCKED. Не повышать статус массово по наличию связанного кода. DONE только после фактической приёмки. В каждом финальном рабочем коммите обновлять очередь, затронутые исходные TODO, MASTER_TODO, CURRENT_TASK и счётчики без повторения отчёта; показывать владельцу список новых CODE READY, остаток, реальные проверки и SHA. Ограничения на БД, совместимость и релиз сохраняются.

## Владелец не программист — правило от 27.11.2026

- Технические параметры (актуальная рабочая C#-база и SQL Server, строки подключения без раскрытия секретов, пути, версии, штатный лаунчер, состояние установки) определять самостоятельно по исходникам, настройкам, ярлыкам, процессам и разрешённым SQL-метаданным. Не просить владельца искать/называть то, что доступно агенту локально.
- Спрашивать только о пользовательском результате, неоднозначном выборе или действительно необходимом разрешении. Перед таким вопросом провести доступную проверку; технические последствия объяснять обычным языком, сообщая уже найденный конкретный объект действия.
- Не повторять полученное разрешение и не перекладывать на владельца технические действия. Сохранять ограничения безопасности и не выдавать отсутствие технических знаний за согласие на неоговорённые действия.

## Экономия токенов, времени и лимита — обязательное правило владельца от 27.11.2026

- Выполнять ровно согласованный запрос одним связанным блоком. Не добавлять попутный аудит, новые функции, переработку архитектуры или рефакторинг. Независимое расширение объёма сначала кратко обозначить и согласовать; найденные несрочные проблемы записать отдельно.
- Читать обязательные инструкции один раз, затем только нужные пункты и изменившиеся сведения. Искать через rg, читать конкретные символы/диапазоны; не перечитывать большие файлы, историю и весь реестр ради небольшой правки.
- Ограничивать вывод инструментов: нужные совпадения, итог и ошибки. Не выводить целые логи, большие JSON, списки инструментов или одинаковые отчёты повторно. Независимые короткие чтения объединять в один вызов.
- Выбирать минимальный достаточный набор проверок по риску изменения. Повторять проверку только после новой правки, ошибки или конкретного неразрешённого риска. Не повторять уже пройденный полный прогон без причины; для документации не собирать программу и не повышать версию.
- Не запускать одновременно сборки, пишущие в один obj/bin. Не совмещать нагрузочные измерения с тяжёлыми тестами. Длительные операции запускать без частого опроса неизменившегося состояния.
- Документировать один раз в обязательных местах: подробности в профильном документе/CHANGELOG, в CURRENT_TASK и MASTER_TODO — краткий результат со ссылкой. Не размножать одинаковые длинные тексты.
- Сообщать кратко: результат, проверки, commit/push и существенный остаток. Не повторять план или обещание скорого окончания. Технические параметры выяснять самостоятельно, не перекладывая их поиск на владельца.
- Закончив и проверив запрос, сразу commit/push в main по действующему разрешению и закончить работу. Не продолжать улучшения ради полноты. Экономия не разрешает пропускать обязательные проверки безопасности, скрывать ошибки или объявлять непроверенное готовым.
